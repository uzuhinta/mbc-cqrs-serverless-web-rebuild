````md
## With the mbc-cqrs-serverless backend (`/mbc`)

The connected pages load and save through the master backend (`/api/master-setting`, `/api/master-data`, `/api/master-bulk`, the copy task endpoints and the sequence package). Give them a client and your router.

**1. A client, once, in a client component:**

```tsx
'use client'
import type { ReactNode } from 'react'
import { MbcProvider } from '@mbc-cqrs-serverless/master-web'
import {
  createMbcClient,
  MbcClientProvider,
} from '@mbc-cqrs-serverless/master-web/mbc'
import { fetchAuthSession } from 'aws-amplify/auth'

const client = createMbcClient({
  apiUrl: 'https://api.example.com',
  // Read on every request and on every render (also on the server).
  tenantCode: () => 'my-tenant',
  getAuthToken: async () =>
    (await fetchAuthSession()).tokens?.idToken?.toString(),
  realtime: {
    url: 'https://example.appsync-api.ap-northeast-1.amazonaws.com/graphql',
    auth: { type: 'API_KEY', apiKey: 'da2-…' },
  },
})

export function MasterProviders({ children }: { children: ReactNode }) {
  return (
    <MbcClientProvider client={client}>
      <MbcProvider locale="ja">{children}</MbcProvider>
    </MbcClientProvider>
  )
}
```

**2. Your routes, as a `MasterRouting`.** The pages link and navigate through it; the package has no routing of its own. Ids in targets are decoded (`MASTER#tenant#MASTER_SETTING#PRODUCT`); encode them in your URLs. With the Next App Router:

```tsx
'use client'
import Link from 'next/link'
import { useRouter } from 'next/navigation'
import { useMemo } from 'react'
import type {
  MasterRouting,
  MasterTarget,
} from '@mbc-cqrs-serverless/master-web'

const id = encodeURIComponent

export function hrefOf(to: MasterTarget): string {
  switch (to.screen) {
    case 'settings':
      return '/master'
    case 'newSetting':
      return '/master/new'
    case 'setting':
      return `/master/${id(to.id)}`
    case 'data':
      return `/master/${id(to.settingId)}/data`
    case 'newData':
      return `/master/${id(to.settingId)}/data/new`
    case 'dataItem':
      return `/master/${id(to.settingId)}/data/${id(to.id)}`
    case 'copyRequest':
      return `/master/${id(to.settingId)}/copy/new`
    case 'copyTasks':
      return `/master/${id(to.settingId)}/copy`
    case 'copyTask':
      return `/master/${id(to.settingId)}/copy/${id(to.taskId)}`
  }
}

export function useMasterRouting(): MasterRouting {
  const router = useRouter()
  return useMemo<MasterRouting>(
    () => ({ href: hrefOf, navigate: (to) => router.push(hrefOf(to)), Link }),
    [router]
  )
}
```

**3. A page per route:**

```tsx
'use client'
// app/master/[settingId]/data/[id]/page.tsx
import { useParams } from 'next/navigation'
import { editorRenderers } from '@mbc-cqrs-serverless/master-web/editors'
import { MbcMasterDataEditorPage } from '@mbc-cqrs-serverless/master-web/mbc'
import { useMasterRouting } from '@/app/master/routing'

export default function DataItemPage() {
  const params = useParams<{ settingId: string; id: string }>()
  return (
    <MbcMasterDataEditorPage
      routing={useMasterRouting()}
      // Next gives the URL-encoded segment; the page encodes ids itself.
      settingId={decodeURIComponent(params.settingId)}
      id={decodeURIComponent(params.id)}
      components={editorRenderers}
      onError={(error) => console.error(error)}
    />
  )
}
```

| Page                          | Route (above)                       | Props besides `routing`, `onError`, `paths`                                                                      |
| ----------------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `MbcMasterSettingListPage`    | `/master`                           | `state` / `onStateChange` (kept inside without them), `inputSampleJson`, `mapRawItem`, `onBack`                  |
| `MbcMasterSettingEditorPage`  | `/master/new`, `/master/[id]`       | `id` (none creates), `onSaved(id)`, `onDeleted()`, `canCopy`, `settingOptions`, `formats` or `formatSettingCode` |
| `MbcMasterDataListPage`       | `/master/[settingId]/data`          | `settingId`, `state` / `onStateChange`, `inputSampleJson`, `mapRawItem`                                          |
| `MbcMasterDataEditorPage`     | `…/data/new`, `…/data/[id]`         | `settingId`, `id` (none creates), `onSaved(id)`, `onDeleted()`, `components`                                     |
| `MbcMasterCopyRequestPage`    | `/master/[settingId]/copy/new`      | `settingId`, `loadTenants(): Promise<{ code; name }[]>`, `onRequested()`, `state` / `onStateChange`              |
| `MbcMasterCopyTaskListPage`   | `/master/[settingId]/copy`          | `settingId`, `pollMs`                                                                                            |
| `MbcMasterCopyTaskDetailPage` | `/master/[settingId]/copy/[taskId]` | `settingId`, `taskId`, `pollMs`                                                                                  |

- **After a write** the pages go on as 0.0.x did: a new setting opens its data list, a new record opens itself, a deleted setting returns to the settings list, a copy request opens the copy results. `onSaved` and `onDeleted` only tell you; do not navigate in them as well.
- **Errors** show on the page, and every failed load or write also reaches `onError` (show a toast there, if your app has them). A write cut short by leaving the page is not reported. A `MbcTimeoutError` means the outcome is unknown: the data editor keeps Save off so that a second save cannot number a duplicate.
- **Ids that change** start the page afresh, also when your router re-uses the page component.
- **Sequences.** The settings editor offers the records of the `sequence_setting` master as the formats an auto-numbered code can use (as 0.0.x did). Pass `formats` to choose them yourself, or `formatSettingCode` to read another master.
- **Copy task results** reload on Refresh; pass `pollMs` to reload that long after each answer.

### Tenants

The current tenant is `client.tenantCode()`. A setting or record belongs to the tenant in its `tenantCode`; another tenant's items, `common` included, open read-only (no Save, Delete, Restore, field reordering or JSON import), and their links still work. `canCopy` on the settings editor shows the copy links; whether a user may copy is your app's decision (0.0.x showed them to one system tenant). Reaching the copy pages is your routing.

`tenantCode` runs during render, on the server too, so it must not need the browser. Compare and pass the tenant exactly as the backend stores it.

### Realtime

Writes are commands: the page waits for the backend's `finish:FINISHED` message over AppSync realtime, so a page that opens a new item finds it stored. Without `realtime`, a write ends as soon as the request is accepted; a newly created item may not be readable yet, and a list reloaded after an import may not show its rows yet.

### With React Router

```tsx
import type { ReactNode } from 'react'
import { useMemo } from 'react'
import { Link, useNavigate } from 'react-router'
import type { MasterRouting } from '@mbc-cqrs-serverless/master-web'
import { hrefOf } from './routes' // the same hrefOf as above

function RouterLink(props: {
  href: string
  className?: string
  children: ReactNode
}) {
  return (
    <Link to={props.href} className={props.className}>
      {props.children}
    </Link>
  )
}

export function useMasterRouting(): MasterRouting {
  const navigate = useNavigate()
  return useMemo<MasterRouting>(
    () => ({
      href: hrefOf,
      navigate: (to) => void navigate(hrefOf(to)),
      Link: RouterLink,
    }),
    [navigate]
  )
}
```

React Router's `useParams()` gives decoded values: pass them to the pages as they are.

### Hooks and the API

For your own pages: `useMasterApi()` (the API on the provider's client), `useMasterSettings(state)`, `useMasterSetting(id)`, `useMasterDataList(settingId, state)`, `useMasterData(id)`, `useCopyTasks(settingCode, { pollMs })`, `useCopyTask(id, { pollMs })`, and `useMasterMutations()`. Each write there has `run` (resolves `undefined` on failure, the error is in `error`) and `runOrThrow` (rejects with the write's own error, which the screens need).

`createMasterApi(client, { paths })` works without React, on a server too. Bulk import sends batches of 100 (the backend's limit); a failed batch rejects with `MasterBulkError` (`done`, `from`, `to`). Every path can be changed:

export const settings = () =>

## Field renderers

The data editor renders each field with the built-in for its type (`defaultRenderers`). Replace any of them with `components`:

```tsx
'use client'
import type { FieldRendererProps } from '@mbc-cqrs-serverless/master-web'

export function ColorField(props: FieldRendererProps) {
  return (
    <input
      type="color"
      id={props.id}
      value={typeof props.value === 'string' ? props.value : '#000000'}
      onChange={(event) => props.onChange(event.target.value)}
      onBlur={props.onBlur}
      disabled={props.disabled}
      aria-invalid={props.invalid || undefined}
      aria-describedby={props.describedBy}
    />
  )
}

// <MasterDataEditor components={{ string: ColorField }} … />
```

A renderer gets `field`, `value` (`FieldRendererProps['value']`), `onChange`, `onBlur`, `id` (the label points at it), `labelId` (for a group of inputs), `describedBy`, `invalid` and `disabled`.

'use client'
import '@mbc-cqrs-serverless/master-web/editors.css'
import { editorRenderers } from '@mbc-cqrs-serverless/master-web/editors'
import { MbcMasterDataEditorPage } from '@mbc-cqrs-serverless/master-web/mbc'

- Each editor shows a plain text box on the server and until its library has loaded (with `import()` after mount), so nothing else waits for them. `RichTextEditor`, `MarkdownEditor` and `JsonEditor` are also exported for your own forms.
- **Styles:** `editors.css` holds Quill's and jsoneditor's styles, scoped to their own classes. Keep `editors-assets/` beside it if you copy the file. The Markdown editor imports its own CSS from JavaScript; if your bundler drops CSS imported that way, add `import '@uiw/react-md-editor/markdown-editor.css'`.
- **CSP:** Ace (inside jsoneditor) adds `<style>` elements, so `style-src` needs `'unsafe-inline'`, and jsoneditor starts its JSON worker from a `data:` URL, so `worker-src` needs `data:`. Where that cannot be allowed, leave `json` out of `components`.
- **Size:** jsoneditor with Ace is about 1 MB minified. Only pages that render a JSON field with `JsonEditor` load it.
- The editors stay light in dark mode, and their own toolbar text is the libraries' English.

  parseMasterSetting,
  toFormValues,
  validateMasterData,
} from '@mbc-cqrs-serverless/master-web/core'

export function checkImport(json: string) {
  // The import dialog's rules; each error carries its entry's index.
  return parseBulkJson(json, { screen: 'settings' })
}

export function checkRecord(storedSetting: unknown, storedRecord: unknown) {
  const setting = parseMasterSetting(storedSetting)
  const record = parseMasterData(storedRecord)
  if (!setting.success) throw setting.error
  if (!record.success) throw record.error
  const fields = dataFields(setting.data)
  // The data editor's rules: required, length, pattern, min, max, valid JSON.
  return validateMasterData(fields, toFormValues(fields, record.data), {
    mode: 'update',
  })
}
```
````

````md
## 3. `IUrlProvider` → `MasterRouting`

Each page takes `routing: { href(target), navigate(target), Link? }`. A target names a screen and its decoded ids.

| `IUrlProvider`                                            | Target                                            |
| --------------------------------------------------------- | ------------------------------------------------- |
| `SETTINGS_PAGE_URL`                                       | `{ screen: 'settings' }`                          |
| `ADD_SETTINGS_PAGE_URL`                                   | `{ screen: 'newSetting' }`                        |
| `EDIT_SETTINGS_PAGE_URL` + `/<pk>/<sk>`                   | `{ screen: 'setting', id }`                       |
| `DATA_PAGE_URL` + `?typeCode=…&typeCodeId=…`              | `{ screen: 'data', settingId }`                   |
| `ADD_DATA_PAGE_URL`                                       | `{ screen: 'newData', settingId }`                |
| `EDIT_DATA_PAGE_URL` + `/<pk>/<sk>`                       | `{ screen: 'dataItem', settingId, id }`           |
| `getCopySettingPageUrl(id)`                               | `{ screen: 'copyRequest', settingId }`            |
| `getDetailedCopySettingPageUrl(id)`                       | `{ screen: 'copyTasks', settingId }`              |
| `getDetailedCopySettingPageUrl(id)` + `/<task id>`        | `{ screen: 'copyTask', settingId, taskId }`       |
| the host-specific entries (a category page, the top page) | none; the settings list's back button is `onBack` |

An id is `<pk>#<sk>`, and `settingId` is the setting's id (0.0.x's `typeCodeId`). To keep 0.0.x's URLs, so that bookmarks still work:

```tsx
'use client'
import Link from 'next/link'
import { useRouter } from 'next/navigation'
import { useMemo } from 'react'
import type {
  MasterRouting,
  MasterTarget,
} from '@mbc-cqrs-serverless/master-web'

const base = '/admin/master' // where your master pages live
const enc = encodeURIComponent

/** 0.0.x's two segments: `MASTER#<tenant>` and the rest. */
function keys(id: string) {
  const at = id.indexOf('#', id.indexOf('#') + 1)
  return `${enc(id.slice(0, at))}/${enc(id.slice(at + 1))}`
}

const setting = (settingId: string) =>
  `typeCode=${enc(settingId.slice(settingId.indexOf('MASTER_SETTING#')))}&typeCodeId=${enc(settingId)}`

export function hrefOf(to: MasterTarget): string {
  switch (to.screen) {
    case 'settings':
      return `${base}/master-setting`
    case 'newSetting':
      return `${base}/master-setting/new`
    case 'setting':
      return `${base}/master-setting/${keys(to.id)}`
    case 'data':
      return `${base}/master-data?${setting(to.settingId)}`
    case 'newData':
      return `${base}/master-data/new?${setting(to.settingId)}`
    case 'dataItem':
      return `${base}/master-data/${keys(to.id)}?${setting(to.settingId)}`
    case 'copyRequest':
      return `${base}/master-setting/${keys(to.settingId)}/copy/new`
    case 'copyTasks':
      return `${base}/master-setting/${keys(to.settingId)}/copy`
    case 'copyTask':
      return `${base}/master-setting/${keys(to.settingId)}/copy/${enc(to.taskId)}`
  }
}

export function useMasterRouting(): MasterRouting {
  const router = useRouter()
  return useMemo<MasterRouting>(
    () => ({ href: hrefOf, navigate: (to) => router.push(hrefOf(to)), Link }),
    [router]
  )
}
```

## 5. Tenants, copying and host-specific parts

0.0.x had one app's rules built in. They are props now, off by default:

- **Who may copy** (0.0.x: one system tenant code) → `canCopy` on the settings editor page.
- **The copy destinations** (0.0.x: a host-specific endpoint read by fixed column names) → `loadTenants(): Promise<{ code: string; name: string }[]>` on the copy request page.
- **The copy request** (0.0.x: a host-specific endpoint) → the framework's `POST /api/master-setting/copy`. Change it with `paths.copy`.
- **Extra setting flags** (0.0.x: labels for two host-specific flags) → `settingOptions: { key: string; label: string }[]`, stored in `attributes` as before.

## 7. Behaviour changes

Stored settings and records keep their shapes. What behaves differently:

**Saving**

- Writes go through `client.command()`: each waits for the backend's completion message, and a `<step>:FAILED` message is reported as a failure.
- Saving unchanged data succeeds quietly.
- A save that timed out says the outcome is unknown. After a create, Save stays off so that a second save cannot number a duplicate record.
- Ids are URL-encoded in request paths.

**Bulk import**

- Items are sent in batches of 100 (0.0.x sent one request and failed above 100), with progress per item. A failed batch stops the import and the dialog says how many went in.
- The JSON dialog is a normal dialog; it no longer drags or resizes.

**Copying**

- Choosing "specified tenants" with none chosen asks for a tenant (0.0.x copied to every tenant).
- "Chosen data only" with no row ticked copies all the data, as before, and now says so.
- A tenant's result says the copy succeeded once its task has completed (0.0.x said so for every task without an error).
- Copy task times show in the browser's time zone after the page has loaded.

**Pages and screens**

- No health-check request, no global loading overlay, no toasts.
- List state (filters, page, sort) is kept inside a page unless you pass `state` and `onStateChange`, for example to keep it in the URL as 0.0.x did.
- Another tenant's setting or record opens read-only, `common` included, as before; the tenant is `client.tenantCode()`.
- Auto-numbered codes use 0.0.x's two sequence requests and their paths (`/api/sequence`, `/api/sequence/with-provided-setting`). The sequence package's own route is `provided-setting`: set `paths` if your backend mounts it as is.

**Editors**

- Tab moves on from the rich editors instead of indenting.
- The Markdown preview does not render raw HTML or script links.
- The editors load after the page has rendered; until then their fields are text boxes.
````
